How it works

We decide before your agent acts.

Every time your agent reaches for a tool, its platform pauses the call and asks us first. We score the action against how that agent normally works. Then we allow it, hold it for a person, or block it. The tool runs only if we say yes.

At the hook

Agent platforms have a step where a tool call is ready but hasn’t run. A small connector puts us at that step. One engine, one small connector for each platform.

Using it

Most of the time, you won’t notice it.

There are no rules to write. Each agent gets its own baseline, learned from its own work. Actions that fit run as usual. You hear from us only when one doesn’t.

ALLOW

It runs.

The tool runs and returns its result. Nothing changes for you or the agent.

HOLD

A person decides.

The action waits. Someone on your team approves it once or keeps it blocked. Nothing runs until then.

BLOCK

It never runs.

The agent gets Blocked by Agentic GUARDIANS back instead of a result, with the reason.

One run, step by step

  • Steps 1 to 3 match how this agent works, so they run.
  • Step 4 is new for this agent. It waits for a person.
  • Step 5 doesn’t fit its baseline. It’s blocked before it runs, and the agent gets the reason.

You teach it. Review a block and mark it right or wrong. That agent’s baseline learns. Other agents are unaffected.

No system is perfect. That’s why holds go to a person, and every block can be reviewed.

How it decides

We read actions, not prompts.

An attack on an agent usually arrives as text: a hidden instruction in a file, a page or a message. We don’t read that text. We look at what the agent does next.

What we look at

  • Which tool the agent calls
  • In what order
  • Compared with that agent’s own baseline

What we don’t read or store

  • Prompts
  • Messages
  • Files

Why another AI can’t be the guard

A common answer is a second model that reads the agent’s prompts. But that guard reads the same text the agent reads. Text that misleads the agent can mislead the guard.

  • No AI in the decision, so there’s nothing to talk around.
  • If we can’t check an action, it doesn’t run.
  • Runs on your machine, on CPU. Nothing leaves it.
  • Blocks and holds can carry a signed record (Ed25519), chained so any tampering shows. Verify it with our public key.

Each record is signed with our private key, and anyone can check it with our public key. Each record also links to the one before it, so a changed or deleted record shows.

Why now

Agents now act with real access.

They read mail, edit code and run commands with real keys. When one is misled, its keys still work, so every system says yes. Checks on who the agent is pass. Logs show the damage after it happened.

The missing check is on what the agent does, at the moment it does it. That’s the one we built.
