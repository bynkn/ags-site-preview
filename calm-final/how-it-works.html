How it works

We watch what your agent does, and stop what doesn’t fit.

Agentic GUARDIANS learns each agent’s behavioral fingerprint from its own work. It scores every action before it runs. When an action doesn’t fit, it holds it for a person or blocks it, and says why.

Why

A compromised agent doesn’t look compromised.

Same keys. Same access. Someone else’s intent.

A hidden instruction in a file can change what an agent does. Every credential is still valid, so every system says yes. Checks on who the agent is pass. Logs show the damage after it happened.

Why another AI can’t be the guard

The usual answer is a second model that reads the agent’s prompts and output. But that guard reads the same text the agent reads. A prompt that misleads the agent can mislead the guard. Its answers also vary: same input, different answers.

How

Five steps, before every tool call.

We score the sequence of tool calls: which tool, in what order, against that agent’s own history. We never read the arguments or commands, and we never read the prompt.

  1. 1

    Connect.

    We sit between your agent and its tools, so we see every action before it runs.

  2. 2

    Learn.

    We learn each agent’s normal from its own behavior and work. No rules to write. Each agent gets its own baseline. When something new is legitimate, you approve it once and it becomes part of that baseline.

  3. 3

    Spot the drift.

    We check every action against its fingerprint, with math. The score is statistical, not a model’s opinion. Same sequence, same score.

  4. 4

    Stop.

    Allow it, hold it for a person, or block it, before it runs. Every block comes with the reason. A blocked tool call never runs: the agent gets Blocked by Agentic GUARDIANS back instead of a result. A person can review it in the console and mark it right or wrong, and the agent’s baseline learns from that.

  5. 5

    Prove.

    Blocks and holds can carry a signed record (Ed25519), chained so any tampering shows. Verify it with our public key.

One run, step by step

  • Steps 1 to 3 match how this agent normally works, so they run.
  • Step 4 doesn’t match its history. It waits for a person to allow or reject it.
  • Step 5 deviates from its fingerprint. It is blocked before it runs, the agent gets the block back, and the block is signed.

What makes it different

No language model in the decision.

The decision is made by math on the agent’s actions. There is nothing to persuade, and nothing for a prompt to reach.

Proof

Not a log. A record.

Blocks and holds can carry a signed record (Ed25519), chained so any tampering shows. Verify it with our public key.

Each record names the agent, the tool, the decision and the reason, and points to the record before it. Change one record and its signature, and every record after it, stop checking out.
